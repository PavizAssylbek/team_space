# team_space

Минимальный frontend Teamspace на React, TypeScript и Vite с готовым UI на Mantine.

## Требования

- Node.js: `^20.19.0 || >=22.12.0`.
- pnpm: `10.15.1` (версия закреплена в `package.json`).

## Установка

В корне репозитория:

```sh
pnpm install
```

## Локальный запуск

```sh
pnpm dev
```

Открой адрес, который Vite напечатает в терминале (обычно `http://localhost:5173`).
На стартовой странице отображаются заголовок «Teamspace» и демонстрационный список
задач с названиями и статусами. Фильтр «Статус задачи» предлагает «Все»,
«К выполнению», «В работе» и «Готово». По умолчанию показаны все задачи.
`TaskList` показывает «Нет задач», если получает пустой массив через props.

Кнопка «Создать задачу» справа в шапке открывает Drawer справа. Форма принимает
только название: пустое значение и одни пробелы показывают ошибку под полем.
Название сохраняется без пробелов по краям, `id` генерируется автоматически,
статус новой задачи — `todo` («К выполнению»). После создания или отмены форма
закрывается и очищается. Задачи хранятся в памяти страницы: перезагрузка возвращает
демонстрационный набор. Выбранный фильтр при создании сохраняется.

## Проверки

```sh
pnpm typecheck
pnpm lint
pnpm build
```

- `typecheck` проверяет TypeScript-код приложения и конфигурацию Vite.
- `lint` запускает Oxlint из официального шаблона Vite.
- `build` проверяет TypeScript и создаёт production-сборку в `dist/`.

Для локального просмотра готовой сборки:

```sh
pnpm preview
```

Постоянная инфраструктура автоматизированных тестов пока не настроена.
Ручная проверка UI:

1. При открытии страницы видны «Teamspace» и три демонстрационные задачи.
2. По очереди выбери каждый статус: остаются только соответствующие задачи.
3. Верни «Все»: исходный список и порядок восстанавливаются.
4. На наборе данных без выбранного статуса появляется «Нет задач». Текущий
   демонстрационный набор содержит все статусы; этот сценарий проверяется
   отдельно через `filterTasksByStatus` и `TaskList`.
5. Открой «Создать задачу»: справа появляется Drawer, фокус находится в поле
   «Название задачи».
6. Отправь пустое название и одни пробелы: под полем появляется ошибка,
   количество задач не меняется.
7. Введи название с пробелами по краям и отправь форму кнопкой или Enter:
   создаётся одна задача без крайних пробелов, со статусом «К выполнению».
8. После успешного создания снова открой форму. Затем получи ошибку, закрой форму
   и открой её снова: поле и ошибка очищены. Закрытие кнопкой «Отмена», крестиком,
   Escape или нажатием на фон не создаёт задачу и возвращает фокус на кнопку открытия.
9. Создай задачу при фильтре «Готово»: фильтр сохраняется, новая задача скрыта.
   Она появляется при выборе «К выполнению» или «Все». Перезагрузка страницы
   удаляет созданные задачи и возвращает три демонстрационные задачи.
10. Проверь отсутствие ошибок и предупреждений в консоли браузера.

## Структура

```text
src/
├── main.tsx                  # Подключение React к DOM
├── app/
│   ├── index.tsx             # MantineProvider и композиция приложения
│   └── index.module.scss     # Явные глобальные базовые стили
├── pages/
│   └── home/
│       ├── index.ts          # Публичный API страницы
│       ├── model/
│       │   └── demo-tasks.ts # Демонстрационные данные страницы
│       └── ui/
│           └── home-page/
│               ├── index.tsx # Стартовая страница
│               └── index.module.scss
├── features/
│   ├── task-create/
│   │   ├── index.ts          # Публичный API создания
│   │   └── ui/
│   │       └── task-create/
│   │           └── index.tsx # Кнопка, Drawer и валидация формы Mantine
│   └── task-filter-status/
│       ├── index.ts          # Публичный API фильтра
│       ├── model/
│       │   └── filter-tasks-by-status.ts
│       └── ui/
│           └── task-status-filter/
│               ├── index.tsx # Управляемый NativeSelect Mantine
│               └── index.module.scss
└── entities/
    └── task/
        ├── index.ts          # Публичный API сущности
        ├── model/
        │   ├── types.ts      # interface Task и enum TaskStatus
        │   └── status-labels.ts # Общие подписи статусов
        └── ui/
            └── task-list/
                ├── index.tsx # Список через props и пустое состояние
                └── index.module.scss
```

Слои FSD добавляются по мере появления функциональности. Направление импортов:
`app` → `pages/home` → `features/task-create` / `features/task-filter-status` →
`entities/task`, через публичные API слайсов. Фичи не импортируют друг друга.
Страница также напрямую использует `TaskList` сущности.
`TaskList` отвечает за отображение сущности, не загружает данные и не меняет
полученный массив. Фича фильтра содержит выбор статуса и функцию фильтрации.
Фича создания хранит ввод и ошибку, валидирует название и передаёт новый `Task`
странице через `onCreate`. Страница хранит массив задач и выбранный статус,
добавляет задачи функциональным обновлением и вычисляет видимый список.
`null` означает «Все» и не добавляется в доменный enum `TaskStatus`.
Демонстрационные данные принадлежат странице; HTTP API и постоянного хранения нет.

## UI на Mantine

Установлены `@mantine/core` и `@mantine/hooks` версии `9.7.1`. Все зависимости
устанавливаются обычной командой `pnpm install`.

В `src/app/index.tsx` один `MantineProvider` включает светлую тему; там же подключён
`@mantine/core/styles.layer.css`. Стили библиотеки находятся в CSS-слое `mantine`,
поэтому собственные SCSS Modules могут переопределять их. Заголовки страницы
используют готовый `Title` с сохранением семантики `h1` / `h2`.

`TaskList` также использует Mantine: `Box component="ul"` сохраняет список,
`Paper component="li"` оформляет строки, `Group` располагает название и статус,
`Text` выводит подписи и пустое состояние «Нет задач». Отступы, границы, фон
и типографика задаются компонентами и темой; SCSS Module содержит раскладку списка
и правила переноса длинных названий.

Для стандартных элементов используем компоненты Mantine. Дополнительные обёртки
создаём при конкретной необходимости. PostCSS-пресет для текущего подключения
готовых стилей и обычных SCSS Modules не требуется; специальные миксины из примеров
Mantine пока не используются. Фильтр использует готовый `NativeSelect` с видимой
подписью; локальное оформление хранится в SCSS Module фичи.
Создание использует `Button`, `Drawer`, `Stack`, `TextInput`, `Group` и
`useDisclosure` из уже установленных пакетов. Собственных правил оформления
для формы нет, поэтому дополнительный SCSS Module не создаётся.

Документация: [подключение с Vite](https://mantine.dev/guides/vite/),
[стили Mantine](https://mantine.dev/styles/mantine-styles/).

## Соглашения

- Объектные контракты и props описываем через `interface`, именованные конечные
  наборы доменных значений — через строковый `enum`. Алиасы `type` используем,
  только когда эти конструкции не подходят. `import type` и `export type`
  остаются корректным способом импортировать и экспортировать интерфейсы.
- Файлы и папки исходников — kebab-case, например `task-list`; имена компонентов,
  интерфейсов и enum остаются PascalCase. Канонические документы (`AGENTS.md`,
  `README.md`, `PROGRESS.md`, `ROADMAP.md`) сохраняют стандартные имена.
- В сегменте `ui` каждый компонент находится в собственной папке:
  `ui/task-list/index.tsx` и `index.module.scss`. Если в папке несколько связанных
  UI-компонентов, используем описательные имена `task-list-item.tsx` /
  `task-list-item.module.scss` и публичный `index.ts`.
- Локальные классы SCSS Modules доступны через `styles`. Только базовые правила
  `:root` и `body` в `app/index.module.scss` явно глобальны.
  Для компиляции SCSS установлен Sass как devDependency.
- Алиас `@/` указывает на `src` и настроен в TypeScript и Vite. Между слайсами
  используем публичный API, например `@/entities/task`; внутри слайса разрешены
  относительные импорты с максимум двумя `../`.

## Коммиты

Используем [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/):

```text
<type>[optional scope][!]: <description>
```

Тип пишем строчными буквами; область (`scope`) необязательна. Описание — короткое
действие на английском, без точки в конце. Например:

```text
feat(tasks): add status filtering with Mantine
fix(tasks): restore all tasks when clearing the filter
docs: document commit conventions
```

- `feat` — новая функциональность; `fix` — исправление ошибки.
- `docs` — только документация; `refactor` — изменение структуры без изменения поведения.
- `style` — форматирование кода без изменения поведения; оформление интерфейса
  классифицируем по цели изменения.
- Также используем `perf`, `test`, `build`, `ci`, `chore` и `revert` по назначению.
- Несовместимые изменения отмечаем `!` перед двоеточием или footer
  `BREAKING CHANGE:` с описанием последствий.

Один коммит содержит связное изменение и относящуюся к нему документацию.
Перед коммитом просматриваем подготовленный diff и выполняем применимые проверки.
Правила для агента закреплены в [AGENTS.md](AGENTS.md); автоматическая проверка
сообщений коммитов пока не настроена.
