# Teamspace — план обучения AI Engineering

Обновлено: 2026-10-10 (Asia/Aqtau).
Текущий этап: неделя 1 из 26. Фактические результаты: [PROGRESS.md](PROGRESS.md).

## Цель и подход

За шесть месяцев развить навыки AI-augmented Fullstack / AI Engineer на основе
существующего опыта React и TypeScript. Основной учебный проект — Teamspace:
управление рабочими пространствами, проектами и задачами с AI-ассистентом.

План восстановлен из учебного чата «План обучения AI Engineering». Это рабочая
программа: сроки и глубина тем пересматриваются по практике и результатам проверок.
Номер недели обозначает учебный этап, а не жёсткую календарную дату.

- Используем frontend-опыт как основу; базовые React, HTML и CSS заново не проходим.
- Backend начинаем с HTTP и жизненного цикла запроса, затем вводим NestJS и БД.
- Практику с coding agents начинаем с первой недели; LLM-функции добавляем по мере
  готовности продукта и понимания способов их проверки.
- Новые технологии добавляем для конкретных задач.
- Реализация агентом и самостоятельное освоение темы учитываются отдельно.

### TaskList — реализация завершена, самостоятельный разбор впереди

Созданы доменные типы `Task` и `TaskStatus` в `entities/task/model`, компонент
`TaskList` в `entities/task/ui/task-list` и публичный API сущности. Список получает массив
через props; страница связывает его с локальными демонстрационными данными.
`Task` описан интерфейсом, `TaskStatus` — строковым enum; стили модульные SCSS,
импорты между слайсами используют алиас `@/` и публичные API.
Размещение стартовой страницы описано в [ADR 0001](docs/decisions/0001-frontend-architecture.md).

Критерии приёмки:

1. Непустой список отображает название и статус каждой задачи; у элементов есть
   стабильный ключ `task.id`.
2. Пустой список отображает «Нет задач».
3. Компонент не загружает данные и не изменяет полученный массив.
4. Импорты между слоями проходят через публичный API `entities/task`.
5. Пустой и непустой сценарии проверены; typecheck, lint и build проходят.
6. Пользователь может объяснить выбор слоя, сигнатуру props и ограничения проверок.

Критерии 1–5 проверены агентом; критерий 6 требует самостоятельного объяснения
пользователя. Ближайший шаг — просмотреть diff и объяснить выбор FSD-слоя,
readonly props, проверку пустого массива и полноту подписей статусов.

По выбору пользователя подключён [Mantine](https://mantine.dev/core/package/)
9.7.1: core/hooks, провайдер в `app`, стили библиотеки и `Title` на странице.
Собственные стили остаются [Sass Modules](https://mantine.dev/styles/sass/).

Следующая функция — фильтрация по статусу отдельной небольшой задачей.
HTTP API и асинхронные состояния рассматриваются позже. TanStack Router
и TanStack Query остаются возможными дальнейшими инструментами и пока не установлены.

## Целевой результат программы

Работающий Teamspace с авторизацией, workspaces, участниками и ролями, проектами,
задачами и изоляцией данных. AI-ассистент помогает искать задачи, суммировать
состояние проекта и предлагать действия с учётом прав пользователя.

Качество подтверждается подходящими тестами, CI, наблюдаемостью, AI-evals,
документированными решениями и практикой развёртывания. Это целевой объём,
а не описание уже реализованных возможностей.
